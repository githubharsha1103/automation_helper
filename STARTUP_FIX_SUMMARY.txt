WHAT WAS WRONG
==============

The controller crashed at runtime with:
  AttributeError: module 'telegram.ext.filters' has no attribute 'STICKER'

This happened because the previous fix used filters.STICKER, which doesn't exist
in python-telegram-bot v20.7.

The root cause: Not verifying against the ACTUAL installed library version.


INVESTIGATION PROCESS
=====================

1. Detected installed version: python-telegram-bot 20.7

2. Listed all available filters in telegram.ext.filters

3. Discovered filters.Sticker is a NAMESPACE, not a filter:
   - filters.Sticker is a class/namespace
   - filters.Sticker.ALL is the actual filter instance
   - filters.Sticker.VIDEO, .REGULAR, .MASK, .CUSTOM_EMOJI also exist

4. Tested filter combinations:
   ✗ filters.Sticker | ... → TypeError (can't use | on class)
   ✓ filters.Sticker.ALL | ... → Works perfectly

IMPORTANT PYTHON-TELEGRAM-BOT PATTERNS
======================================

In PTB 20.7+, filter attributes use this pattern:

  NAMESPACE filters:
    • filters.Sticker.ALL / .VIDEO / .REGULAR / .MASK / .CUSTOM_EMOJI
    • filters.Document.ALL (or specific types)
    • filters.ChatType.GROUP / .SUPERGROUP / .PRIVATE / .CHANNEL

  Simple filters:
    • filters.TEXT

LESSON LEARNED
==============

Never assume filter names. Always:
1. Check telegram.__version__
2. List available filters: [x for x in dir(filters) if not x.startswith('_')]
3. Test filter combinations before deployment
4. Run runtime validation, not just syntax checks (py_compile can pass but runtime can fail)
